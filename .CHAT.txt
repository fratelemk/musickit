❯ Can we know which song is playing currently on my Mac in Apple Music?         

⏺ Not from the browser directly — there's no web API that exposes what another
  macOS app is playing. But locally on your Mac you have a few practical paths:

  1. AppleScript (simplest): osascript -e 'tell application "Music" to get 
  {name, artist, album} of current track' returns the currently playing track.
  You could run this from a tiny local Node/Python server and have the React app
   fetch it.
  2. Tauri/Electron wrapper: lets the same React UI shell out to AppleScript (or
   the private MediaRemote framework for system-wide "Now Playing", which also
  covers Spotify/browser audio).
  3. Last.fm "now playing" API: if you scrobble, you can query your own recent
  track over HTTPS — works from a pure browser app, no native code.

  Which of those fits what you're building? If you want, I can wire up option 1
  with a small local server so the page polls and displays the current track.

❯ Can I switch tracks with osascript?                                           

⏺ Yes. Apple Music exposes playback control via AppleScript, so osascript can
  drive it from the terminal:

  osascript -e 'tell application "Music" to next track'      # forward
  osascript -e 'tell application "Music" to previous track'  # back
  osascript -e 'tell application "Music" to playpause'       # toggle
  osascript -e 'tell application "Music" to play'
  osascript -e 'tell application "Music" to pause'

  You can also jump to a specific track by ID/name, set volume (set sound volume
   to 50), or seek (set player position to 30). Combined with the get current 
  track query I mentioned, that's enough to build a full remote: a tiny local
  HTTP server with /now-playing, /next, /prev, /playpause endpoints that shell
  out to osascript, and your React page hits them with fetch. Want me to
  scaffold that server?

  process that does, and the React app talks to it over HTTP.

  Minimal shape:

  - Server (Node, ~30 lines with the built-in http + child_process.execFile):
    - GET /now-playing → runs osascript to read current track, returns JSON

  - Frontend: fetch('http://127.0.0.1:7891/next', { method: 'POST' }) etc., and

❯ Is there any chance to get BPM for each song in our library? Can we use an    
  external service?                                                             

⏺ A few practical options, in rough order of usefulness:

  1. Already in the XML — Apple Music has a BPM field per track. Your library
  probably has it blank for most tracks (Apple doesn't auto-fill), but check
  firstTrack.BPM in the console — anything you've set manually is already there
  for free.
  2. Spotify Web API — Audio Features (best external option). For a track ID,
  the /audio-features endpoint returns tempo (BPM as a float), plus key, energy,
   danceability, etc. Coverage is wide. Workflow: search Spotify by artist + 
  name → get track ID → fetch features. Requires a free developer app for OAuth
  (client credentials flow, no user login needed).
  3. GetSongBPM API (getsongbpm.com). Free with attribution required, lookup by
  artist+title, returns BPM directly. Simpler than Spotify, smaller catalog,
  rate-limited.
  4. Local audio analysis — libraries like web-audio-beat-detector or
  essentia.js can compute BPM from the actual audio file. Most accurate but
  requires reading the audio file off disk; from a browser that means another
  endpoint on the local server (Node can read the path stored in Location for
  each track) and either streaming the audio to the page or analyzing
  server-side.

  My recommendation: start with #1 (free, instant), and fall back to Spotify 
  Audio Features for tracks where it's missing. Want me to wire up Spotify
  lookup behind a server endpoint (so the client secret stays out of the
  browser)?
